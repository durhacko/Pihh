## 1. Rules for Phase 2 on the demo path

1. **At most two Phase 2 items on the judged demo path** (decision D7). The judged path is the 90-second script plus the 60–90 s table pitch in [`DEMO_PLAN.md`](DEMO_PLAN.md). The candidates are `P2-B1` (C2) and `P2-B2` (C1). The roadmap recommends `P2-B1` only if it is rehearsed by 07:30 after a recorded presenter rehearsal (rung 0b). For `P2-B2` it recommends only the repro and headless results, not the live readout, and the repro only if `P2-WP-02` was in review by 06:30 and merged. Every other beat belongs to the 3-minute script, to hands-on time at the table, or to after the hackathon.
2. **Everything is off by default.** X-ray alone is not off: the script turns X-ray on from 12 s to 82 s, and layers self-register. So each Phase 2 view draws only when its own URL flag is set **and** X-ray is on: `?p2=cascade` for `P2-B1`, `?p2=inv` for the `P2-B2` readout ([work packages §2.1](../development/PHASE2_WORK_PACKAGES.md#21-track-h-hackathon-window)). The layer reads the flag once in `init`, it defaults to off, and it needs no `main.ts` edit. Without the flag the scripted demo looks exactly as it does today.
3. **The script does not change.** `DemoScript.ts`, its ticks, seed `101` and its events stay as they are. A Phase 2 beat may only add something to look at during an existing beat. Phase 2 code is renderer-side or observer-side, so the scripted run's `stateHash` must be identical with the beat on and off (`P2-G5`).
4. **Performance budget.** Each addition costs at most 0.5 ms per tick per world at `n0` = 200, timed opt-in with `P2_PERF=1` (`P2-T10`, `P2-T18`; method in [PHASE2_EVALUATION §12](../validation/PHASE2_EVALUATION.md#12-performance-criteria)). The frame budget is [experience §10](../design/experience-and-demo.md#10-performance): "both worlds ≤ 3 ms" (SHOULD). Browser checks reuse the #118 harness (`scripts/perf/run.mjs`, [QA](QA.md)) rather than a new timing framework. The 0.5 ms covers simulation-side `ingest` only, not the extra draw calls. X-ray is already the slow mode: the only recorded browser run (software rendering, [`assets/qa/perf.md`](../../assets/qa/perf.md)) gives 14.24 sim ticks/s for "single view + X-ray" against 19.98 without, and the beat timings assume 20. So each X-ray beat (`P2-B1`, `P2-B2`) also needs the harness's "single view + X-ray" and "split view + X-ray" rows with the layer on and off, on the presentation laptop; the beat is dropped if sim ticks/s falls measurably below the layer-off value. The quality ladder (#126) has merged since the audit base. Each Phase 2 layer implements the optional `Layer.setQuality?(level)` and hides itself at every level above 0 ([work packages §2.4](../development/PHASE2_WORK_PACKAGES.md#24-performance-rule)), so the rehearsal must also confirm the level stays 0 on the presentation laptop. Otherwise the beat silently disappears.
5. **Time box and cut order.** The beats follow the global trigger, the rungs and the 07:30 merge close in the [roadmap](../planning/PHASE2_ROADMAP.md#emergency-cut-order); a global cut means no Phase 2 beat is shown. Rung 0b (no presenter rehearsal of the 90 s script recorded in DEMO_PLAN by 06:00) cuts every Track H visual: `P2-B1`, the `P2-B2` readout, the composer part of `P2-B3` and the minimal `P2-B6`. Otherwise, mapped to beats, the order is `P2-B4` and the minimal `P2-B6` (rung 2), `P2-B3` (rung 3), the live readout in `P2-B2` (rung 4), `P2-B1` (rung 5), and the repro in `P2-B2` last (rung 6; it leaves the D7 candidates if `P2-WP-02` is not in review by 06:30). Anything not merged, tested and browser-checked by 07:30 stays on its branch. Tag `demo-good-<n>` before every Phase 2 merge.
6. **Base work is never presented as Phase 2.** These are all base work: gossip (#105), paced targets (#96), the composer and console (#112), the timeline (#109), the Encore brain in the app (#107), the scripted demo (#104, #119), the app shell that mounts the composer, inspector and ghost slots (#113), the CLI Encore arm (#116), the perf harness (#118), the evidence matrix (#122), the sensing order (#82), the render quality ladder (#126), the freeze run (#137) and the backup video recorder (#131, #148).
